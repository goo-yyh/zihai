# zihAI 后续行动计划

更新日期：2026-08-17

## 使用说明

本文档只保留尚未完成的工作。已经落地并通过本地质量门禁的代码优化、图片策略统一、事务并发保护、查询优化、后台游标分页、审计日志筛选、首页公开项目搜索/排序/无限滚动和相关单元测试不再重复列出。

当前目标是先完成安全上线所需的外部环境和真实链路验证，再补齐生产可观测性与自动化测试，最后根据真实数据决定性能和产品扩展方向。

## P0：正式上线前必须完成

### 1. 准备隔离的服务环境

- [ ] 分别创建 Development、Preview、Production 的 Neon 数据库。
- [ ] 分别创建对应的 Vercel Blob Store。
- [ ] 为三套环境生成不同的 `BETTER_AUTH_SECRET`。
- [ ] 为本地、预览域名和生产域名分别登记 GitHub、Google OAuth 回调。
- [ ] 为 Preview 和 Production 配置独立的 Resend API Key，并验证 `auth@aioff.dev` 发信。
- [ ] 在 Vercel 中配置全部必需环境变量。
- [ ] 确认只有 `NEXT_PUBLIC_SITE_URL` 暴露给浏览器。
- [ ] 确认 Preview 环境不能读写 Production 数据或 Blob。

完成标准：三套环境不共享数据库、Blob 令牌、OAuth Secret、Resend API Key 或认证签名密钥；每个 OAuth 回调地址与对应环境完全一致。

### 2. 在 Preview 验证数据库迁移

- [ ] 运行 `make db-check-preview`，使用 `staging` 分支的 Preview `DATABASE_URL` 检查迁移。
- [ ] 人工检查 `drizzle/` 中尚未部署的 SQL。
- [ ] 在 Preview 数据库运行 `make db-migrate-preview`。
- [ ] 确认数据库结构与 `src/db/schema` 一致。
- [ ] 确认 URL 异或、唯一点赞、迭代所有者和图片数量触发器均已存在。
- [ ] 确认 Neon 已配置符合业务要求的时间点恢复或备份策略。
- [ ] Preview 冒烟测试通过后，再从受控发布任务或可信工作站迁移 Production。

完成标准：迁移在 Preview 成功执行，约束验证通过，并且已经记录生产迁移的执行人、时间、命令和回滚边界。

### 3. 完成 Preview 关键链路冒烟测试

至少准备一名普通用户和一名管理员，逐项记录测试人、时间、环境、结果和失败证据。

#### 认证与权限

- [ ] GitHub 登录成功。
- [ ] Google 登录成功。
- [ ] 首次登录必须进入引导流程。
- [ ] Google 登录默认使用 Google 邮箱作为私密联系邮箱。
- [ ] GitHub 返回邮箱时默认使用该邮箱；GitHub 未返回邮箱时必须手动填写有效联系邮箱。
- [ ] `qq.com` 和 `163.com` 身份邮箱完成一次性图片验证码后可以发送并验证 OTP；错误、过期、重复使用或邮箱不匹配的图片验证码，以及绕过页面直接调用发送端点的请求均会被拒绝；其他邮箱域名、子域名和伪装后缀也会被拒绝，私密联系邮箱不受此限制。
- [ ] 完成引导后可以使用用户名和密码登录，并可在账户设置中设置或修改密码。
- [ ] 未完成引导不能创建项目、迭代或点赞。
- [ ] 未登录用户不能访问 `/dashboard` 和 `/settings`。
- [ ] 非管理员不能访问 `/admin`。
- [ ] 最后一名管理员不能被降级或删除。

#### 图片与 Blob

- [ ] OAuth 头像、自定义头像和缺失/失效 OAuth 图片时的默认头像均可正常使用，Header 不发生布局错位。
- [ ] JPEG、PNG、WebP 上传成功。
- [ ] 不支持的 MIME 类型和超限文件被拒绝。
- [ ] 项目和迭代可上传 1～3 张图片，第 4 张被拒绝。
- [ ] 图片排序、删除和头像替换后页面缓存正确刷新。
- [ ] 删除项目、迭代、图片和账号后，数据库与 Blob 没有错误引用。
- [ ] 模拟持久化失败时，新上传 Blob 能被补偿删除。

#### 项目与审核生命周期

- [ ] 创建项目时必须满足网站 URL 与 GitHub URL 二选一。
- [ ] 单个用户的全部状态项目合计不能超过 10 个，并发创建不能突破上限；删除项目后可以再次创建。
- [ ] 草稿可以提交审核。
- [ ] 管理员通过后，项目出现在首页、项目页和用户主页。
- [ ] 驳回原因在工作台可见，修改后可以重新提交。
- [ ] 修改已通过项目后，公开页立即隐藏并重新进入待审核。
- [ ] 已通过项目可以创建迭代。
- [ ] 待审核迭代不公开，也不会导致父项目下线。
- [ ] 迭代通过后出现在对应项目的公开更新日志中。
- [ ] 点赞与取消点赞正常，同一用户不能重复点赞。

#### 后台与分页

- [ ] 项目、迭代、用户和审计日志列表准备超过 25 条测试数据。
- [ ] 上一页、下一页和返回第一页均正常工作。
- [ ] 同一时间戳的数据翻页时不重复、不丢失。
- [ ] 项目/迭代状态筛选翻页后仍然保留。
- [ ] 用户搜索翻页后仍然保留。
- [ ] 审计日志目标类型和关键词筛选翻页后仍然保留。
- [ ] 无效、过长或跨页面复用的游标不会产生 500 错误。

#### 首页发现与分页

- [ ] 首页默认选中“最新”，并按发布时间从近到远排列。
- [ ] “最热”按点赞数排列，同热度项目使用发布时间稳定排序。
- [ ] 标题或描述关键词搜索均能命中，并与“最新”或“最热”组合生效。
- [ ] 准备超过 12 个已通过项目，滚动到底部后能继续加载且不重复、不丢失。
- [ ] 切换排序或关键词时重置为第一页，不混入上一组筛选结果。
- [ ] 点击刷新按钮后回到页面顶部，并重新查询当前筛选条件的第一页。

#### SEO 与公开页面

- [ ] 首页、项目页和用户页的标题、描述、Canonical 与 Open Graph 正确。
- [ ] `/robots.txt` 和 `/sitemap.xml` 使用生产规范域名。
- [ ] 草稿、待审核、已驳回和已归档内容不会进入公开查询或 Sitemap。
- [ ] 项目和用户不存在时返回正确的 404 与禁止索引元数据。

完成标准：所有阻断级问题已经关闭；失败场景有日志或截图；修复后完成回归测试。

### 4. 完成发布质量门禁

- [ ] 在配置完整的环境运行 `pnpm format`。
- [ ] 运行 `pnpm check`，确认格式、Lint、类型、全部单元测试和生产构建通过。
- [ ] 确认 GitHub Actions 在最终提交上通过。
- [ ] 确认部署与 CI 验证的是同一个 Git Commit。
- [ ] 检查工作树中没有调试代码、Mock、占位数据、未处理 TODO 或意外文件。

完成标准：最终发布 Commit 的本地门禁和 CI 均通过，没有因为环境变量缺失而跳过生产构建。

### 5. 准备生产发布与回滚

- [ ] 先发布 Preview，并完成全部 P0 冒烟测试。
- [ ] 设置生产域名、`BETTER_AUTH_URL` 和 `NEXT_PUBLIC_SITE_URL`。
- [ ] 应用生产迁移后，再发布依赖该结构的应用版本。
- [ ] 使用 `pnpm admin:promote <邮箱>` 提升首位生产管理员。
- [ ] 记录上一版本 Vercel Deployment。
- [ ] 记录发布前 Neon 恢复点。
- [ ] 编写应用回滚、停止迁移和数据库恢复步骤。

完成标准：团队明确知道应用回滚不会自动回滚数据库；发生迁移或 Blob 故障时，有可执行的停止发布和恢复流程。

## P1：上线后第一周完成

### 1. 增加真实数据库集成测试

优先覆盖单元测试无法证明的数据库与并发行为：

- [ ] 项目 URL 异或约束。
- [ ] 同一用户并发点赞的唯一性。
- [ ] 并发上传无法突破三张图片上限。
- [ ] 项目/迭代提交与图片回调并发时状态一致。
- [ ] 两名管理员并发审核时只有一次有效状态转换和一条正确审计记录。
- [ ] 两名管理员并发撤权时不会删除最后一名管理员。

完成标准：测试使用一次性数据库或事务隔离，不依赖生产数据，并能在 CI 中稳定重复运行。

### 2. 增加 Playwright 端到端测试

- [ ] 未登录访问与权限重定向。
- [ ] Email OTP 与 OAuth 测试替身进入引导流程，并覆盖 `qq.com`/`163.com` 身份邮箱白名单、邮箱/Google 默认值、GitHub 缺失邮箱时的必填规则，以及用户名密码登录和密码修改。
- [ ] 创建项目、上传图片、提交、管理员审核和公开展示。
- [ ] 修改已通过项目、公开页隐藏和重新审核。
- [ ] 创建、提交和审核迭代。
- [ ] 后台筛选、搜索和游标分页。
- [ ] 加载态、错误提示和移动端关键布局。

完成标准：关键链路可以在隔离测试环境或 Preview 运行；失败时保留 Trace、截图和视频。

### 3. 加入生产级限流与滥用防护

优先保护登录、上传意图、Blob 回调、点赞、提交审核和管理员写操作。限流状态必须存放在适合 Serverless 多实例部署的共享存储中，不能使用仅当前进程有效的内存计数器。

- [ ] 选择限流存储和服务方案。
- [ ] 定义用户 ID、IP、动作和时间窗组合规则。
- [ ] 为正常用户、匿名用户和管理员定义不同阈值。
- [ ] 返回稳定且不泄露内部实现的安全错误。
- [ ] 增加限流命中日志、监控和告警。

完成标准：多实例环境下限流一致；模拟超限请求时能够阻断滥用，正常上传和审核链路不受影响。

### 4. 建立生产可观测性

- [ ] 选择并接入异常监控平台。
- [ ] 区分 Route Handler、Server Action、数据库和 Blob 错误。
- [ ] 使用结构化日志记录动作和资源标识。
- [ ] 确保日志不包含 Cookie、Token、密码、OAuth Secret 或敏感正文。
- [ ] 监控登录失败率、上传失败率、审核积压、5xx、数据库延迟和 Blob 清理失败。
- [ ] 为关键指标配置阈值、通知渠道和负责人。

完成标准：模拟一次数据库故障和一次 Blob 故障都能触发告警，并能从日志定位到动作和资源。

### 5. 完善浏览器安全策略

- [ ] 在 Preview 启用 Content Security Policy Report-Only。
- [ ] 收集并分析真实违规报告。
- [ ] 覆盖 Next.js、Better Auth、Vercel Blob 图片和必要的 OAuth 跳转。
- [ ] 避免宽泛的 `*`，不要长期依赖 `unsafe-eval`。
- [ ] 确认登录、上传、Markdown 和管理后台无回归后启用强制 CSP。

完成标准：正式 CSP 已启用，关键功能正常，不需要通过放宽全部来源解决单点兼容问题。

## P2：稳定运行后的优化工作

### 1. 用真实数据决定索引和缓存

- [ ] 对首页热门/最新项目、公开项目详情、审核队列、分页列表和用户搜索运行 `EXPLAIN (ANALYZE, BUFFERS)`。
- [ ] 记录数据量、执行计划、查询耗时和缓冲区命中情况。
- [ ] 根据慢查询证据决定是否增加复合或部分索引。
- [ ] 评估 Next.js 16 Cache Components。
- [ ] 明确公开数据、用户会话和管理数据的缓存边界及失效标签。

完成标准：每个新增索引或缓存都有基准数据、预期收益、失效策略和回滚方式。

### 2. 建立 Blob 对账与孤儿清理任务

- [ ] 定期比较数据库中的 `blobPathname` 与 Blob Store 对象清单。
- [ ] 默认只输出 dry-run 报告。
- [ ] 为孤儿对象设置保留期，禁止发现后立即删除。
- [ ] 记录清理对象、执行人、时间和结果。
- [ ] 对清理失败配置监控和重试。

完成标准：任何自动删除都会先产生精确对象列表；数据库仍引用的文件不会被清理任务删除。

### 3. 改善审核运营

- [ ] 根据审核量决定是否增加队列 SLA、负责人或领取状态。
- [ ] 为常见驳回原因提供可编辑模板。
- [ ] 根据运营需求决定是否增加审计日志导出。
- [ ] 根据实际积压决定是否增加审核通知。

### 4. 建立产品指标

建议优先定义：

- 引导完成率。
- 项目提交率。
- 审核通过率。
- 首次审核耗时。
- 发布后点赞率。
- 迭代发布率。
- 30 天活跃开发者数。

完成标准：每个指标都有明确事件、分母、去重规则和隐私说明；分析工具不采集密码、Token 或用户上传的敏感正文。

### 5. 再评估产品功能扩展

只有 P0、P1 稳定后，再根据用户证据考虑分类标签、收藏、评论、通知或团队账号。首页标题/描述搜索与中英文界面切换已经落地，不再列为后续功能。

新增公开字段必须接入统一审核生命周期，不能绕过 `content-lifecycle.ts`；新增文件模型必须同时保存展示 URL 与可删除 Pathname，并明确数据库与 Blob 的失败补偿顺序。

## 每次发布的固定检查清单

- [ ] 工作树只包含本次发布范围内的改动。
- [ ] `pnpm format` 与 `pnpm check` 通过。
- [ ] Schema 变更已通过 `make db-generate` 生成新迁移、人工检查 SQL，并运行目标环境的 `make db-check-*`。
- [ ] 所有新请求边界都有服务端 Zod 校验。
- [ ] 所有写操作都重新检查会话、角色和所有权。
- [ ] 所有公开字段变更都进入统一审核生命周期。
- [ ] Blob 操作明确写出数据库与对象存储的先后顺序和补偿逻辑。
- [ ] 所有受影响页面都通过 `src/server/cache.ts` 失效。
- [ ] 成功、加载和安全错误反馈仍然可见。
- [ ] Preview 冒烟测试通过，监控没有新增异常。
- [ ] 已记录发布 Commit、迁移、操作者、时间和回滚入口。

## 明确不要做的事情

- 不要在应用启动时自动同步或修改生产数据库。
- 不要修改已经进入共享环境的历史迁移。
- 不要把数据库、OAuth、认证或 Blob 密钥改成 `NEXT_PUBLIC_` 变量。
- 不要把 Proxy、按钮隐藏或客户端校验当成授权边界。
- 不要在 Action、上传回调或组件中复制审核状态转换规则。
- 不要使用进程内存实现生产限流。
- 不要在没有查询计划和真实指标时盲目增加缓存或索引。
- 不要为了快速上线跳过最后管理员保护、图片补偿清理或公开字段审核。
